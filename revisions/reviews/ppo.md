핵심 키워드:
clipped surrogate objective, 신뢰영역 근사, 병렬 액터, minibatch 재사용
주요 전략:
한 번의 갱신으로 정책이 너무 많이 바뀌지 않도록 비율을 잘라낸다
사용 가능 분야:
연속 제어, 게임, 그리고 이후 RLHF의 표준 최적화 알고리즘

#### 배경 지식

**policy 를 갱신한다는 게 무엇을 바꾸는 것인가**

Transformer 기반 정책이라면 갱신되는 것은 다음과 같다.

- **Self-Attention 가중치 (Q, K, V 행렬)** — query, key, value의 가중치가 갱신된다.
- **Feed-Forward 가중치** — FFN에서 GELU 같은 비선형 함수로 사라지는 값을 조절할 수 있다. 가중치를 더하거나 빼서 특정 성질에 대한 벡터값이 바뀌면, 역전파를 통해 중요도에 따른 제외나 강조가 가능해진다.
- **Layer Normalization 파라미터** — 각 feature에 대한 정규화를 통해 위와 같이 특징별 중요도 조절이 가능해진다.
- **Positional Embedding** — 토큰 단위로 위치가 임베딩돼 있다고 하면, 각 토큰의 임베딩이 더 관련 있는 토큰과 가까워지도록 조정된다. 의미론적 표현이 증대된다.

즉 "정책을 갱신한다"는 것은 이 파라미터들을 **보상을 최대화하는 방향으로** 조금씩 움직이는 것이다.

```python
# 보상을 최대화하는 방향으로
gradient = ∇_θ (보상 - KL페널티)

# 각 파라미터를 조금씩 수정
새_가중치 = 기존_가중치 + learning_rate * gradient

# 너무 큰 변화 방지
if 변화량 > clip_범위:
    변화량 = clip_범위
```

**왜 갱신 폭을 제한해야 하는가**

정책 경사 방법의 고질적인 문제는 **한 번의 갱신이 너무 커지면 정책이 망가진다**는 것이다. 망가진 정책으로 수집한 데이터는 다시 학습을 망치므로 회복이 어렵다.

TRPO는 이를 KL 발산에 대한 제약으로 풀었는데, 2차 최적화가 필요해서 구현이 복잡하고 비싸다. **PPO는 같은 효과를 1차 최적화로, 목적함수를 자르는 것만으로 얻는다.**

#### PPO 알고리즘

**핵심 — clipped surrogate objective**

정책 비율을 `r(θ) = π_θ(a|s) / π_old(a|s)` 로 두면, 목적함수는 이렇게 된다.

```text
L = E[ min( r(θ)·A,  clip(r(θ), 1-ε, 1+ε)·A ) ]
```

`A`는 advantage다. 비율이 `[1-ε, 1+ε]` 범위를 벗어나면 잘라내므로, **그 방향으로 더 가봐야 목적함수가 개선되지 않는다.** 자연스럽게 갱신 폭이 제한된다.

**전체 절차**

1. **N개의 병렬 액터로 데이터를 수집한다.**
2. 수집된 데이터로 **일정 에폭 동안 minibatch 학습**으로 정책을 최적화한다.
3. 정책을 갱신한다.
4. **clipping으로 정책 변화가 너무 커지지 않게 막는다.**

**동작 방식**

![그림 2](/img/rlhf/02.png)

1. 병렬 액터가 환경을 동시에 실행한다. 각 환경은 독립적으로 에이전트와 상호작용한다.
2. 현재 상태 `S_t`와 보상 `R_t`를 에이전트에게 전달한다.
3. 에이전트가 PPO 알고리즘을 실행한다.
   - 병렬 액터들에게서 받은 데이터를 수집한다.
   - 수집된 데이터를 일정 에폭 동안 minibatch 학습으로 최적화한다.
   - 정책을 갱신한다.
4. 갱신된 정책으로 행동 `A_t`를 결정한다. **모든 환경에서 같은 정책을 쓰지만 행동은 다를 수 있다.**
5. 반복한다.

**왜 데이터를 여러 에폭 재사용할 수 있는가**
일반적인 정책 경사는 온폴리시라 한 번 쓴 데이터를 버려야 한다. PPO는 비율 `r(θ)`로 중요도를 보정하고 clipping으로 안전 범위를 강제하므로, **같은 배치를 여러 에폭 돌려도 무너지지 않는다.** 샘플 효율이 개선되는 지점이다.

#### 정리

PPO에서 가져갈 것은 알고리즘 자체보다 **"갱신 비율을 잘라 안전 범위를 강제한다"**는 형태다.

이 골격은 반복적으로 갱신되는 어떤 시스템에도 붙일 수 있다. 신뢰영역을 2차 최적화로 정확히 계산하는 대신, 목적함수를 잘라서 **더 가봐야 이득이 없게** 만드는 것이다. 근사이지만 구현이 단순하고 실제로 잘 동작한다.

다만 대가가 있다. **하이퍼파라미터에 민감하고 구현 세부가 성능을 좌우한다.** 정규화 방식, clipping 범위, 가치 함수 clipping 여부 같은 것들이다. 재현성 문제가 잘 알려져 있는 알고리즘이기도 하다.
