핵심 키워드:
텍스트 기반 브라우징 환경, 행동 모방, rejection sampling, 출처 인용
주요 전략:
브라우저 조작을 명령어 텍스트로 정의해서, 검색 행동 자체를 언어 모델링 문제로 바꾼다
사용 가능 분야:
장문 질의응답, 그리고 이후 도구 사용·에이전트 연구의 원형

#### 개괄

웹 브라우저 검색을 활용해 **긴 글로 답해야 하는 질문**에 GPT-3가 답하도록 파인튜닝한다.

- 사람이 특정 질문에 답하기 위해 **웹 브라우저에 접속해 어떻게 행동하는가**를 학습해 파인튜닝한다.
- **행동을 텍스트로 토큰화**해서 토큰 단위 loss로 학습한다.
- 이를 통해 사람의 행동을 모사해 정보를 retrieval하고 종합하는 방식을 학습한다.
- 추론 시에는 **rejection sampling**으로 여러 답변을 생성하고, 보상 모델 기준 최고 점수 답변을 출력한다.

#### 배경 지식

**기존 접근과의 차이**

REALM이나 RAG 같은 기존 질의응답 연구는 **주어진 질의에 대한 문서 검색을 개선**하는 데 집중했다. 검색 자체를 학습으로 좋게 만드는 것이다.

WebGPT는 다르게 간다. **이미 있는 검색엔진(Bing)을 그대로 쓴다.** 논문이 밝히는 이유는 두 가지다.

1. **현대 검색엔진은 이미 매우 강력하고**, 최신 문서를 대량으로 색인하고 있다.
2. 그래서 **더 높은 수준의 과제에 집중할 수 있다.** 검색엔진을 써서 질문에 답하는 일은 사람이 잘하는 것이고, 언어 모델이 모방할 수 있는 것이다.

검색 품질을 올리는 문제와, 검색을 **사용하는** 문제를 분리한 셈이다.

#### 환경 설계

텍스트 기반 웹 브라우징 환경을 만들었다. 언어 모델은 현재 상태를 텍스트로 받고, 그에 대해 **명령어 하나를 발행**한다.

**행동 명령어 체계**

| 명령어 | 효과 |
|---|---|
| `Search <query>` | Bing API에 질의를 보내고 검색 결과 페이지를 표시한다 |
| `Clicked on link <link ID>` | 해당 ID의 링크를 따라 새 페이지로 이동한다 |
| `Find in page: <text>` | 페이지에서 다음 등장 위치를 찾아 스크롤한다 |
| `Quote: <text>` | 현재 페이지에서 해당 텍스트를 찾으면 **참고문헌으로 추가**한다 |
| `Scrolled down <1, 2, 3>` | 지정한 횟수만큼 아래로 스크롤한다 |
| `Scrolled up <1, 2, 3>` | 지정한 횟수만큼 위로 스크롤한다 |
| `Top` | 페이지 맨 위로 이동한다 |
| `Back` | 이전 페이지로 돌아간다 |
| `End: Answer` | 브라우징을 끝내고 답변 단계로 넘어간다 |
| `End: <Nonsense, Controversial>` | 브라우징을 끝내고 답변을 건너뛴다 |

이 외의 텍스트를 생성하면 **무효 행동**으로 처리한다. 무효 행동도 최대 횟수에는 포함되지만 그 외에는 무시된다.

**작동 루프**

1. 모델이 현재 상태를 보고 명령어 하나를 발행한다.
2. 환경이 그 명령을 실행한다. Bing 검색, 링크 클릭, 스크롤 등이다.
3. **새 컨텍스트로 이 과정을 반복한다.**

여기서 중요한 설계가 하나 있다. 매 스텝마다 컨텍스트가 새로 시작되므로, **이전 스텝에 대한 유일한 기억은 요약에 기록된 내용뿐이다.** 모델이 무엇을 기억할지를 스스로 관리해야 한다.

**출처 기록**
브라우징 중 `Quote` 행동을 하면 **페이지 제목, 도메인 이름, 발췌문이 기록**된다. 나중에 답변의 참고문헌으로 쓰인다. 답변에 근거를 붙이는 것이 구조에 내장돼 있는 셈이다.

#### 학습 과정

**1. 데이터 수집과 모방 학습**

인간 사용자가 실제로 웹 브라우저를 써서 질문에 답하는 과정을 기록한다.

- 예를 들어 *"How to train crows to bring me gifts"* 같은 질문에 답하기 위해 검색하고 정보를 찾는 **모든 행동**을 수집한다.
- 이 데모 데이터로 GPT-3를 파인튜닝한다. `(질문, [행동1, 행동2, …, 최종답변])` 시퀀스를 학습하는 것이다.

**2. 보상 모델과 rejection sampling**

- 인간이 선호하는 답변 패턴을 학습한 보상 모델을 만든다.
- WebGPT가 생성한 여러 답변 중 **보상 모델의 점수가 높은 것만 선택**한다.

RL로 정책을 갱신하는 대신 **추론 시점에 여러 개를 뽑고 고르는** 방식이다. 학습 없이 추론 계산만으로 성능을 올리는 형태이고, Best-of-N과 같은 골격이다.

#### 정리

WebGPT가 한 일은 **브라우저 조작을 언어 모델링 문제로 바꾼 것**이다.

행동을 명령어 텍스트로 정의하면, 검색하고 읽고 인용하는 일련의 과정이 **하나의 시퀀스**가 된다. 그러면 언어 모델이 이미 잘하는 것 — 다음 토큰 예측 — 으로 환원된다.

여기서 옮겨갈 만한 발상 두 가지가 있다.

**첫째, 행동 공간을 텍스트로 정의하기.** 무엇을 할 수 있는지를 명령어 목록으로 적으면 그 자체가 인터페이스가 된다. 이후 도구 사용과 에이전트 연구가 전부 이 형태를 따른다.

**둘째, 출처 기록을 구조에 내장하기.** `Quote` 행동이 참고문헌을 자동으로 남기므로, 답변에 근거가 붙는 것이 선택이 아니라 기본값이 된다. 검증 가능성을 나중에 붙이는 대신 처음부터 설계에 넣은 것이다.
