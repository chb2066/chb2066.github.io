# 논문 리뷰 개정 — 형식 명세

이 문서는 `src/content/reviews/` 의 리뷰들을 다시 쓸 때 따르는 규칙이다.
**원본은 절대 수정하지 않는다.** 개정본은 `revisions/reviews/<slug>.md` 로 따로 만든다.
사용자가 확인한 뒤 직접 반영할지 결정한다.

기준 형식은 `src/content/reviews/i-jepa.md` 다. 아래는 그 글에서 뽑아낸 규칙이다.

---

## 1. 전체 골격

```markdown
---
(frontmatter — 원본 그대로 유지. link·venue·paper 가 비어 있으면 확인해서 채운다)
---

핵심 키워드:
(이 논문을 한 줄로 특징짓는 개념 2~4개)
주요 전략:
(무엇을 어떻게 해서 그걸 달성했는지)
사용 가능 분야:
(어떤 downstream 에서 쓰이는지)

#### 배경 지식

(이 논문을 읽기 전에 알아야 하는 것. 선행 연구가 무엇을 했고 무엇이 부족했는지.)

#### <논문명> method

(핵심 아이디어. 기존 방식과의 대비를 명시한다.)

#### <논문명> 세부 아키텍처

(모듈별로 역할·구조·입력·출력. 숫자가 있으면 반드시 적는다.)

#### 세부 task를 위한 사용법

(실제로 어떻게 갖다 쓰는지. 텐서 형태나 구체적 절차.)
```

마지막 두 섹션은 논문 성격에 따라 이름을 바꿔도 된다.
예: `#### 학습 방법`, `#### 실험에서 확인된 것`, `#### 한계`.
**섹션을 억지로 채우지 않는다.** 내용이 없으면 그 섹션은 빼는 게 낫다.

## 2. 서술 규칙

### 문장 끝맺음을 통일한다 — 가장 자주 틀리는 부분

원본들은 `~함`, `~됨`, `~한다`, `~이다`, 명사 종결이 한 글 안에서 섞여 있다.
**개정본은 `~한다` / `~이다` 평서형으로 통일한다.**

| 이렇게 | 이렇게 쓰지 않는다 |
|---|---|
| 임베딩 공간에 손실함수를 적용한다 | 임베딩 공간에 손실함수가 적용됨 |
| 붕괴를 막는 장치가 필요하다 | 붕괴 방지 장치 필요 |
| EMA로 천천히 갱신한다 | EMA로 갱신됨 |

불릿 안에서도 마찬가지다. 다만 **표의 칸이나 짧은 라벨은 명사로 끝내도 된다.**

### 문장이 중간에 끊긴 곳을 찾아 완성한다

원본에 `~~~~`, `수정 필요`, `내용 확인`, 문장이 어미 없이 끝난 곳이 있다.
논문을 읽고 채운다. **채울 수 없으면 그 대목을 지운다.** 빈 껍데기를 남기지 않는다.

### 전문용어는 영문 원어로 쓴다

`Knowledge Base` 와 같은 규칙이다. `docs/writing-guide.md` 2-3-2 참조.

| 이렇게 | 이렇게 쓰지 않는다 |
|---|---|
| stop-gradient | 정지기울기 |
| contrastive learning | 대조학습 |
| Action Chunking | 행동 청킹 |

연결하는 문장은 한국어다. 용어만 원어로 둔다.

### 원본에 있는 것을 함부로 버리지 않는다

이 리뷰들은 사용자가 직접 읽고 정리한 것이다.
**개정의 목적은 형식을 맞추고 빈 곳을 채우는 것이지, 내용을 새로 쓰는 게 아니다.**

- 사용자의 판단·의문·관찰(`고찰`, `생각해볼만한 것`)은 **반드시 살린다.** 이게 이 글의 값어치다.
- 사실관계가 틀린 곳만 논문을 근거로 고치고, 고쳤으면 개정 노트에 남긴다.
- 원본에 없던 내용을 추가할 때는 논문에서 확인한 것만 넣는다.

## 3. 그림

원본의 `![그림 N](/img/<slug>/NN.png)` 링크는 **그대로 유지한다.**
Notion 에서 옮겨온 실제 파일이 `public/img/` 에 있다. 경로를 바꾸면 깨진다.

위치가 어색하면 옮겨도 되지만, 링크 문자열 자체는 건드리지 않는다.

## 4. 논문 확인

내용을 채우거나 사실관계를 확인할 때는 **논문을 실제로 받아서 본다.**

```bash
# 초록·서지 정보
curl -s "http://export.arxiv.org/api/query?id_list=<arxiv-id>"

# 전문
curl -sL "https://arxiv.org/pdf/<arxiv-id>" -o paper.pdf
```

- **arXiv ID 를 추측하지 않는다.** API 로 제목을 대조해 일치하는 것만 쓴다.
- frontmatter 의 `venue`, `authors` 가 비어 있으면 확인해서 채운다.
- 확인 못 한 것은 비워둔다. 지어내지 않는다.

## 5. 개정본 머리말

각 개정본 맨 위에 무엇을 고쳤는지 적는다. frontmatter 위에 HTML 주석으로 둔다.

```markdown
<!--
개정: 2026-09-10
- 끝맺음을 평서형으로 통일
- "Contribution / Method / What I doubt" 빈 섹션을 논문 근거로 채움
- venue·authors 확인해 frontmatter 보강
- 원본의 "왜 읽었나" 판단은 그대로 유지
-->
---
title: ...
```
