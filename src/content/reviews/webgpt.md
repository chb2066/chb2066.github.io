[WebGPT: Browser-assisted question-answering with human feedback](https://arxiv.org/abs/2112.09332)

## Abstract

**문제**

- 긴 글로 답해야 하는 질문(long-form QA)은 모델 내부 지식만으로는 근거를 댈 수 없고 최신성도 없음
- 기존 retrieval 연구는 검색 자체를 개선하는 데 집중 → 검색을 사용하는 능력은 따로 남아 있음

**해결책**

- 브라우저 조작을 명령어 텍스트로 정의해 검색 행동 자체를 언어 모델링 문제로 변환
- 사람의 브라우징 데모를 모방 학습하고, 보상 모델 기반 rejection sampling 으로 답변을 고름
- `Quote` 명령으로 출처 인용을 구조에 내장

## 1. Introduction

**기존 접근과의 차이** - REALM 이나 RAG 같은 기존 질의응답 연구는 주어진 질의에 대한 문서 검색을 개선하는 데 집중했다. 검색 자체를 학습으로 좋게 만드는 것이다.

WebGPT 는 다르게 간다. 이미 있는 검색엔진(Bing)을 그대로 쓴다. 논문이 밝히는 이유는 두 가지다.
1. 현대 검색엔진은 이미 매우 강력하고, 최신 문서를 대량으로 색인하고 있음
1. 그래서 더 높은 수준의 과제에 집중할 수 있음 - 검색엔진을 써서 질문에 답하는 일은 사람이 잘하는 것이고, 언어 모델이 모방할 수 있는 것

**개괄**
- 사람이 특정 질문에 답하기 위해 웹 브라우저에 접속해 어떻게 행동하는가를 학습해 파인튜닝함
- 행동을 텍스트로 토큰화해서 토큰 단위 loss 로 학습함
- 이를 통해 사람의 행동을 모사해 정보를 retrieval 하고 종합하는 방식을 학습함
- 추론 시에는 rejection sampling 으로 여러 답변을 생성하고, 보상 모델 기준 최고 점수 답변을 출력함

## 2. Environment design

텍스트 기반 웹 브라우징 환경을 만들었다. 언어 모델은 현재 상태를 텍스트로 받고, 그에 대해 명령어 하나를 발행한다.

**행동 명령어 체계**

| 명령어 | 효과 |
|---|---|
| `Search <query>` | Bing API에 질의를 보내고 검색 결과 페이지를 표시한다 |
| `Clicked on link <link ID>` | 해당 ID의 링크를 따라 새 페이지로 이동한다 |
| `Find in page: <text>` | 페이지에서 다음 등장 위치를 찾아 스크롤한다 |
| `Quote: <text>` | 현재 페이지에서 해당 텍스트를 찾으면 참고문헌으로 추가한다 |
| `Scrolled down <1, 2, 3>` | 지정한 횟수만큼 아래로 스크롤한다 |
| `Scrolled up <1, 2, 3>` | 지정한 횟수만큼 위로 스크롤한다 |
| `Top` | 페이지 맨 위로 이동한다 |
| `Back` | 이전 페이지로 돌아간다 |
| `End: Answer` | 브라우징을 끝내고 답변 단계로 넘어간다 |
| `End: <Nonsense, Controversial>` | 브라우징을 끝내고 답변을 건너뛴다 |

이 외의 텍스트를 생성하면 무효 행동으로 처리한다. 무효 행동도 최대 횟수에는 포함되지만 그 외에는 무시된다.

**작동 루프**
1. 모델이 현재 상태를 보고 명령어 하나를 발행함
1. 환경이 그 명령을 실행함 - Bing 검색, 링크 클릭, 스크롤 등
1. 새 컨텍스트로 이 과정을 반복함

여기서 중요한 설계가 하나 있다. 매 스텝마다 컨텍스트가 새로 시작되므로, 이전 스텝에 대한 유일한 기억은 요약에 기록된 내용뿐이다. 모델이 무엇을 기억할지를 스스로 관리해야 한다.

**출처 기록** - 브라우징 중 `Quote` 행동을 하면 페이지 제목, 도메인 이름, 발췌문이 기록된다. 나중에 답변의 참고문헌으로 쓰인다. 답변에 근거를 붙이는 것이 구조에 내장돼 있는 셈이다.

## 3. Methods

### 3.1 Data collection

인간 사용자가 실제로 웹 브라우저를 써서 질문에 답하는 과정을 기록한다.

- 예를 들어 "How to train crows to bring me gifts" 같은 질문에 답하기 위해 검색하고 정보를 찾는 모든 행동을 수집함
- 답변 쌍에 대한 비교 데이터도 함께 수집해 보상 모델 학습에 사용

### 3.2 Training

**입력 요소** - `(질문, [행동1, 행동2, …, 최종답변])` 시퀀스

- **행동 복제(BC)** - 데모 데이터로 GPT-3 를 파인튜닝
- **보상 모델(RM)** - 인간이 선호하는 답변 패턴을 학습
- rejection sampling (best-of-n) - WebGPT 가 생성한 여러 답변 중 보상 모델의 점수가 높은 것만 선택
- **RL(PPO)** - 정책 자체를 갱신하는 변형도 함께 학습

rejection sampling 은 RL 로 정책을 갱신하는 대신 추론 시점에 여러 개를 뽑고 고르는 방식이다. 학습 없이 추론 계산만으로 성능을 올리는 형태이고, Best-of-N 과 같은 골격이다.

## 4. Evaluation

- **4.1 ELI5** - 사람 데모 및 Reddit 최고 득표 답변과 비교. 175B best-of-64 모델이 양쪽을 앞섬

- **4.2 TruthfulQA** - 참조를 붙이는 구조 덕분에 GPT-3 대비 진실성이 개선
- **4.3 TriviaQA** - 짧은 사실 질의에서도 경쟁력 확인

---

## 5. Experiments

- 5.1 RL 은 best-of-n 없이는 BC 대비 개선이 있지만, best-of-n 과 결합하면 이득이 거의 사라짐 → 두 방법이 같은 축을 다루고 있다는 뜻

- 5.2 정책·보상 모델 크기와 n 을 함께 키우며 확장성 측정. n 을 키우는 것이 상당한 구간까지 계속 이득

## 6. Discussion

- **6.1~6.2 진실성** - 참조를 붙이면 진실해 보이지만, 그럴듯해 보이는 정도가 실제 정확도보다 앞설 수 있음
- **6.3 편향 강화** - 모델이 자기 견해를 뒷받침하는 출처만 고르는 경향
- 6.4 참조는 사실성 평가를 쉽게 만들지만 평가자가 실제로 확인해야 함
- 6.5 실시간 웹 접근 자체가 새로운 위험을 만듦
