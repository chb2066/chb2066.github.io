**Abstract**
기존 상호 작용하는 음성 모델은(EX: 시리, 빅스비) 역할, 목소리가 고정되어 역할 중심적인 프로그램이나 개인화된 상호작용 지원에 한계가 있다.
본 연구는 “역할 부여를 위한 텍스트 프롬프트”와 “음성 복제를 위한 음성 샘플” 을 결합한 하이브리드 시스템 프롬프트를 통합한 모델을 제안한다. 본 모델은 LLM, TTS로 생성한, 프롬프트와 에이전트 대화 쌍으로 구성된 데이터로 학습되었다.
본 모델은 기존의 단일 어시스턴트 역할을 다중 역할 고객 시나리오가 가능하게 확장했다. 실험 결과, 역할 준수, 화자 유사성, 지연 시간, 자연스러움 등 측면에서 좋은 성능을 보였다.

개괄: 역할 묘사 텍스트와 복제하고 싶은 목소리 파일을 넣으면 해당 음성을 바로 복제하고 역할을 부여된 페르소나 모델과 대화할 수 있게 해주는 모델.

#### 3.1. 아키텍쳐

기반 모델: Moshi 아키텍쳐(Temporal Transformer + Depth Transformer 두 단 구조)
입력:
오디오(=유저 목소리), 에이전트 텍스트(=역할 묘사 텍스트),  에이전트 오디오(=목소리 샘플)
프롬프트 구성:
- 텍스트 역할 묘사와 오디오 음성 샘플이 “하이브리드 시스템 프롬프트”에 입력됨.
- “하이브리드 시스템 프롬프트”는 시간 순으로 구성된 두 개의 세그먼트로 구성.
  1. 텍스트 세그먼트: 에이전트 오디오 채널 무음, 텍스트 채널의 특정 시나리오에 맞는 텍스트 토큰을 강제한 프롬프팅을 통해 역할 부여
  1. 음성 세그먼트: 에이전트 텍스트 채널 패딩을 패딩하는 동안, 에이전트 오디오 채널에 짧은 음성 샘플 제공하여 음성 프롬프팅을 수행
- 무음, 패딩 등을 통해 텍스트, 음성 정보가 입력될 때, 다른 정보가 같이 들어오지 않게 한다.
- 위 구성을 통해 텍스트로 역할을 부여하고(음성 채널 비움), 에이전트 오디오 채널에 원하는 사람의 음성 샘플을 입력하여 해당 음성을 제로샷으로 복제(목소리로 사용)할 수 있게 된다. 이후 실제 대화 시작 시 사용자의 음성 입력을 받아 대화가 진행된다.
- 커스템 텍스트/오디오는 구분 기호를 통해 시스템 프롬프트와 실제 대화 간 경계 표시
  - 이를 통해 대화가 섞여서 모델이 대화에 혼선을 갖는 일을 없앰.
- 프롬프트로 가는 역전파는 마스킹하고, 의미없는 오디오 토큰, 패딩 텍스트 토큰은 손실 가중치 낮춤.
  - 시스템 프롬프트는 학습 시키지 않고, 대화 구간에서의 의미가 담긴 대화 토큰 정보만 가중치를 학습시킴.
특이점:
텍스트로 역할을 먼저 부여하고 목소리를 복제하던, 목소리 복제를 먼저하고 텍스트로 역할을 부여하던 성능의 차이는 없으나 논문에서는 추론 시 지연 시간 감소를 위해 음성을 먼저 배치함.

3.2. 합성 데이터 생성
3.2.1. 대화 스크립트 및 텍스트 프롬프트 생성 방법
서비스 시나리오: 서비스 도메인(예: 은행, 레스토랑 등등)을 샘플링한 후 시나리오를 선택하여 LLM 모델의 생성을 통해 2인 대화 스크립트 생성. 서비스 에이전트에게는 이에 해당하는 역할 콘텍스트가 생성된다.
질의응답 어시스턴트 시나리오: 추가로 다양한 주제, 두 번째 질문 시나리오(주제 전환, 후속 질문 등)이 적용된 2턴 질의응답 대화도 합성했다. 이 데이터에서는 고정된 역할 텍스트를 사용했다. "당신은 지혜롭고 친절한 선생님입니다. 질문에 답하거나 조언을 명확하고 흥미로운 방식으로 제공하세요.”
3.2.2. 대화 음성 및 음성 프롬프트 생성
음성 샘플: 합성 대화 음성 및 이에 대응하는 에이전트 음성 프롬프트 생성을 위해 단일 화자 음성 샘플 사용.
서비스 시나리오: 타이밍, 끼어들기, 톤 등을 자연스럽게 하기 위해 다중화자 TTS 모델을 사용해서 두 명의 화자 샘플을 입력 받아 각 목소리를 복제하면서 스크립트에 따라 오디오를 이어서 생성함.
질의응답 시나리오: 단일화자 모델을 사용해 각 턴을 따로 생성 후 스티칭, 묵음 길이로 끼어들기 시뮬레이션
3.3. Service-Duplex-Bench
50개의 고유한 서비스 역할 시나리오로 구성되어 있으며, 각 시나리오 당 7개의 질문을 포함. 대화용 학습 데이터와 달리, 평가용 질문은 주어진 서비스 콘텍스트 내에서 고유 명사 기억, 콘텍스트 준수, 처리 불가능한 요청 처리, 고객의 무례함 대처 등 특정 능력을 테스트하기 위해 설계된 단일 턴 프로브임.
